## Platform
web

## Users
- **Support agents:** work their own tickets and the unassigned queue every day, usually on a laptop and for hours at a time. Speed and scanability matter more than delight.
- **Support leads:** assign, close, reopen and watch SLA breaches and agent load. They have full access.
- **Viewers:** read-only, with customer email masked. Only if self-signup is enabled.
- **Reviewers at Benrey** *(inferred)*: evaluate the build as a take-home. They look for a non-technical-friendly, considered UI that is still the framework's own admin.

## Product Purpose
A support ticket tracker built on the Django admin: customers, agents, tickets with a status workflow and SLA deadlines, comments with attachments, role-based access, and an AI assistant that explains the admin forms. Success means an agent can find, claim and resolve the right ticket without hunting, and a lead can see what's late at a glance.

## Positioning
The UI is generated by Django's own admin tooling (with the Unfold skin), not hand-built. Roles visibly change what each user sees, rather than only blocking requests.

## Operating Context
- Agents and leads work in the browser all day, so the admin is the whole product surface.
- Production runs at https://aleksei-ticket-tracker.fly.dev/admin/. Local development uses Docker on http://localhost:8000/admin/.

## Capabilities and Constraints
- **Status workflow:** new → open, open ↔ pending customer, then resolved and closed. The rules live on the models. A ticket is resolved only after a public agent reply. Closing is Lead-only, and so is reopening a closed ticket (within 14 days).
- **SLA:** urgent 1 h, high 4 h, normal 24 h, low 72 h.
- **Hidden fields:** a field hidden from a role is hidden everywhere — fields, list display, filters, search, autocomplete, error messages and the AI context.
- **Build state:** Phase 0 (skeleton) is done. The ticket models and admins arrive in Phase 1, so today the admin shows only Users and Groups.

## Brand Commitments
- **Design language:** the admin uses benrey.io's design language — dark only, one lime accent, wide oblique display type, uppercase mono labels. See [DESIGN.md](DESIGN.md) and [docs/features/design-language.md](docs/features/design-language.md).
- **Assets:** Benrey's own logo, 3D renders and licensed Base Neue font are not used.

## Evidence on Hand

## Product Principles
1. The tool disappears into the task. Standard admin affordances beat invented ones.
2. Roles change what you see, not just what you may do.
3. Rules are enforced in one place (the models), and the UI only reflects them.
4. Nothing the product shows is fabricated.
